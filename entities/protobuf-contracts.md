# Protobuf Wire Contracts (`market_data.proto`)

The Protocol Buffers contract file `protos/market_data.proto` defines the canonical binary serialization format and wire schemas used across the **Nexus Trading Exchange (NTE)** platform. It establishes the message specifications for market depth snapshots and executed trade events published by the [[entities/order-matching-engine]] over [[entities/kafka-broker]] topics and ingested by the Market Data Gateway (MDG).

---

## Responsibilities

* **Canonical Binary Schema Definition**: Provides language-agnostic schema definitions for all Level 2 (L2) market depth snapshots and trade execution ticks across the exchange architecture.
* **Inter-Service Contract Standardization**: Enforces strict typing and wire compatibility across upstream producers ([[entities/order-matching-engine]]) and downstream consumers, including the MDG ingestion tier ([[entities/order-book-consumer]] and [[entities/trade-consumer]]) and sister systems like the [[entities/compliance-surveillance-monitor]].
* **Efficient Wire Serialization**: Minimizes payload overhead and wire serialization latency over high-throughput [[entities/kafka-broker]] topics (`nte.orderbook.snapshots` and `nte.trades.matched`).
* **Source of Truth for Runtime Envelopes**: Serves as the structural baseline for MDG TypeScript models defined in [[entities/runtime-models]] (`OrderBookEvent`, `TradeEvent`, `PriceLevel`).

---

## Dependencies

* **Upstream Producers**:
  * `[[entities/order-matching-engine]]`: Serializes matched trades and book snapshots into Protobuf binary frames.
* **Downstream Consumers & Gateways**:
  * `[[entities/order-book-consumer]]`: Ingests binary messages conforming to `OrderBookSnapshot`.
  * `[[entities/trade-consumer]]`: Ingests binary messages conforming to `TradeTick`.
  * `[[entities/compliance-surveillance-monitor]]`: Reuses canonical schema contracts for audit, reconstruction, and market surveillance.
* **Runtime Layer**:
  * `[[entities/runtime-models]]`: Translates deserialized Protobuf fields into TypeScript runtime structures and client broadcast envelopes (`L2_UPDATE`, `TRADE_TICK`).

---

## Schema Definitions

The contract is defined under `package nte.marketdata;` using `proto3` syntax.

```protobuf
syntax = "proto3";
package nte.marketdata;

option java_package = "com.gfmg.nte.marketdata";
option go_package = "github.com/astrophage/market-data-gateway/protos";

// Consumed from nte.orderbook.snapshots topic published by order-matching-engine
message OrderBookSnapshot {
    string symbol = 1;
    repeated Level bids = 2;
    repeated Level asks = 3;
    int64 timestamp_ns = 4;
}

message Level {
    double price = 1;
    double quantity = 2;
    int32 order_count = 3;
}

// Consumed from nte.trades.matched topic published by order-matching-engine
message TradeTick {
    string trade_id = 1;
    string symbol = 2;
    double price = 3;
    double quantity = 4;
    int64 matched_at_ns = 5;
    string taker_side = 6;
}
```

## Field Specifications & Semantics

### 1. `OrderBookSnapshot`
Represents the aggregated top-of-book and multi-level depth for a given instrument at a discrete point in time.

| Field | Tag | Type | Description |
| :--- | :--- | :--- | :--- |
| `symbol` | `1` | `string` | Financial instrument symbol (e.g., `"BTC-USD"`). |
| `bids` | `2` | `repeated Level` | Ordered collection of buy limit price levels, sorted in descending order of price. |
| `asks` | `3` | `repeated Level` | Ordered collection of sell limit price levels, sorted in ascending order of price. |
| `timestamp_ns` | `4` | `int64` | Nanosecond epoch timestamp marking when the snapshot was generated by the matching core. |

### 2. `Level`
Represents an individual aggregated price level within the order book.

| Field | Tag | Type | Description |
| :--- | :--- | :--- | :--- |
| `price` | `1` | `double` | Limit price point for the resting volume. |
| `quantity` | `2` | `double` | Cumulative aggregate quantity/volume available at this price point. |
| `order_count` | `3` | `int32` | Number of distinct active limit orders aggregated into this level. |

### 3. `TradeTick`
Represents a finalized trade execution match generated by the matching engine.

| Field | Tag | Type | Description |
| :--- | :--- | :--- | :--- |
| `trade_id` | `1` | `string` | Unique identifier generated for the executed trade match. |
| `symbol` | `2` | `string` | Financial instrument symbol. |
| `price` | `3` | `double` | Execution unit price. |
| `quantity` | `4` | `double` | Total executed quantity. |
| `matched_at_ns` | `5` | `int64` | Nanosecond epoch timestamp when the match was recorded. |
| `taker_side` | `6` | `string` | Aggressor side that triggered the match (`"BUY"` or `"SELL"`). |

## Data Lifecycle & Runtime Mapping

During the [[concepts/data-lifecycle]], messages cross boundaries between internal Kafka topics, runtime deserializers, and external WebSocket broadcasts:

```
[order-matching-engine]
       │ (Protobuf Binary)
       ▼
[Kafka: nte.orderbook.snapshots / nte.trades.matched]
       │ (Protobuf Binary)
       ▼
[OrderBookConsumer / TradeConsumer]
       │ (Deserialized to [[entities/runtime-models]])
       ▼
[ClientManager JSON Broadcast Envelope]
       │ (JSON: L2_UPDATE / TRADE_TICK)
       ▼
[Subscribed WebSocket Clients]
```

1. **Ingestion**: `[[entities/order-book-consumer]]` and `[[entities/trade-consumer]]` receive binary buffers from [[entities/kafka-broker]].
2. **Translation**: The Protobuf fields map to the TypeScript interfaces in `[[entities/runtime-models]]`:
   * `OrderBookSnapshot` $\rightarrow$ `OrderBookEvent`
   * `Level` $\rightarrow$ `PriceLevel`
   * `TradeTick` $\rightarrow$ `TradeEvent`
3. **Egress**: The [[entities/client-manager]] converts runtime objects into JSON envelopes (`L2_UPDATE`, `TRADE_TICK`) for client delivery.
