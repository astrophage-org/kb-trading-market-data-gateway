# Runtime Models & Event Envelopes

The **Runtime Models and Event Envelopes** define the in-memory TypeScript type definitions and client-facing egress schemas utilized across the **Market Data Gateway (MDG)**. Defined primarily in `src/models/types.ts` and constructed within `src/websockets/ClientManager.ts`, these types represent the internal domain abstractions for market state updates and the structured JSON envelopes broadcast over WebSockets to external trading participants and UI egress layers.

---

## Responsibilities

* **Internal Type Safety**: Provides strong TypeScript interfaces for representing aggregated Level 2 (L2) market depth, price levels, and matched trade executions within the application runtime.
* **Schema Decoupling**: Bridges the binary serialization formats defined in [[entities/protobuf-contracts]] to idiomatic JavaScript/TypeScript domain models.
* **Egress Envelope Standardization**: Defines the high-level discriminator wrapper format (`L2_UPDATE`, `TRADE_TICK`) used by [[entities/client-manager]] to dispatch uniform JSON payloads across public WebSocket connections.
* **Data Lifecycle Normalization**: Normalizes wire formats (such as nanosecond epoch timestamps and snake_case fields) into standard application camelCase conventions suitable for downstream consumption.

---

## TypeScript Data Definitions

The core runtime interfaces are declared in `src/models/types.ts`:

```typescript
export interface PriceLevel {
    price: number;
    quantity: number;
    orderCount: number;
}

export interface OrderBookEvent {
    symbol: string;
    bids: PriceLevel[];
    asks: PriceLevel[];
    timestamp: number;
}

export interface TradeEvent {
    tradeId: string;
    symbol: string;
    price: number;
    quantity: number;
    matchedAt: number;
    takerSide: 'BUY' | 'SELL';
}
```

### Field Breakdown

#### `PriceLevel`
Represents an individual aggregated price tier in the order book.
* **`price`** (`number`): Floating-point limit price level.
* **`quantity`** (`number`): Total aggregated resting depth volume at this price level.
* **`orderCount`** (`number`): Aggregate count of individual resting limit orders comprising this level.

#### `OrderBookEvent`
Represents a full L2 snapshot or depth update for a single trading symbol.
* **`symbol`** (`string`): Ticker pair identifier (e.g., `BTC-USD`, `ETH-USD`).
* **`bids`** (`PriceLevel[]`): Array of aggregated buy orders sorted descending by price.
* **`asks`** (`PriceLevel[]`): Array of aggregated sell orders sorted ascending by price.
* **`timestamp`** (`number`): Epoch millisecond timestamp of snapshot generation.

#### `TradeEvent`
Represents an executed order match tick generated by the [[entities/order-matching-engine]].
* **`tradeId`** (`string`): Unique trade match identifier.
* **`symbol`** (`string`): Ticker pair for the executed instrument.
* **`price`** (`number`): Executed price per unit.
* **`quantity`** (`number`): Total executed quantity.
* **`matchedAt`** (`number`): Execution timestamp (epoch milliseconds).
* **`takerSide`** (`'BUY' | 'SELL'`): Order side of the aggressive incoming taker order that triggered the execution.

## Egress WebSocket Event Envelopes

When messages are broadcast to external WebSocket subscribers via [[entities/client-manager]], they are wrapped in standardized JSON event envelopes containing a discriminatory `type` field and the associated `data` payload.

```
+-------------------------------------------------------------+
|                      WebSocket Client                       |
+-------------------------------------------------------------+
                               ^
                               |
    +--------------------------+--------------------------+
    |                                                     |
    | JSON: { type: "L2_UPDATE", ... }                    | JSON: { type: "TRADE_TICK", ... }
    |                                                     |
+---------------------------+             +---------------------------+
|  ClientManager.           |             |  ClientManager.           |
|  broadcastOrderBook()     |             |  broadcastTrade()         |
+---------------------------+             +---------------------------+
```

### 1. `L2_UPDATE` Envelope
Dispatched via `ClientManager.broadcastOrderBook()` when an aggregated order book snapshot is processed by [[entities/order-book-consumer]].

```json
{
  "type": "L2_UPDATE",
  "data": "{\"symbol\":\"BTC-USD\",\"bids\":[{\"price\":65000.0,\"quantity\":1.5,\"orderCount\":3}],\"asks\":[{\"price\":65001.5,\"quantity\":0.8,\"orderCount\":1}],\"timestamp\":1698123456789}"
}
```

### 2. `TRADE_TICK` Envelope
Dispatched via `ClientManager.broadcastTrade()` when a matched trade is processed by [[entities/trade-consumer]].

```json
{
  "type": "TRADE_TICK",
  "data": "{\"tradeId\":\"TRD-9021481\",\"symbol\":\"BTC-USD\",\"price\":65000.5,\"quantity\":0.25,\"matchedAt\":1698123456790,\"takerSide\":\"BUY\"}"
}
```

## Wire Schema vs. Runtime Model Mapping

The runtime models correspond to the binary Protocol Buffer schemas defined in [[entities/protobuf-contracts]]:

| Protobuf Message (`market_data.proto`) | Protobuf Field | Runtime Interface (`types.ts`) | Runtime Field | Transformation Details |
| :--- | :--- | :--- | :--- | :--- |
| `nte.marketdata.OrderBookSnapshot` | `symbol` | `OrderBookEvent` | `symbol` | Direct 1:1 mapping |
| `nte.marketdata.OrderBookSnapshot` | `bids` | `OrderBookEvent` | `bids` | Repeated `Level` messages mapped to `PriceLevel[]` |
| `nte.marketdata.OrderBookSnapshot` | `asks` | `OrderBookEvent` | `asks` | Repeated `Level` messages mapped to `PriceLevel[]` |
| `nte.marketdata.OrderBookSnapshot` | `timestamp_ns` | `OrderBookEvent` | `timestamp` | Nanoseconds (`int64`) converted to milliseconds (`number`) |
| `nte.marketdata.Level` | `price`, `quantity`, `order_count` | `PriceLevel` | `price`, `quantity`, `orderCount` | Snake_case to camelCase conversion |
| `nte.marketdata.TradeTick` | `trade_id` | `TradeEvent` | `tradeId` | Snake_case to camelCase conversion |
| `nte.marketdata.TradeTick` | `matched_at_ns` | `TradeEvent` | `matchedAt` | Nanoseconds (`int64`) converted to milliseconds (`number`) |
| `nte.marketdata.TradeTick` | `taker_side` | `TradeEvent` | `takerSide` | String validation to `'BUY' \| 'SELL'` union |

## Dependencies

* **[[entities/protobuf-contracts]]**: The canonical binary definitions consumed from [[entities/kafka-broker]] topics (`nte.orderbook.snapshots` and `nte.trades.matched`).
* **[[entities/order-book-consumer]]**: Hydrates raw Kafka message buffers into `OrderBookEvent` instances.
* **[[entities/trade-consumer]]**: Hydrates raw Kafka message buffers into `TradeEvent` instances.
* **[[entities/client-manager]]**: Formats runtime models into `L2_UPDATE` and `TRADE_TICK` JSON strings for high-throughput fan-out.
* **[[concepts/data-lifecycle]]**: Governs the pipeline where wire formats are transformed into runtime models and emitted as client event envelopes.
* **[[concepts/websocket-broadcasting]]**: Utilizes these envelopes to perform non-blocking egress dispatching.
